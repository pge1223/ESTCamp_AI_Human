## 2026-06-16 강사님 스크럼 — RAG 한계 진단 & 방향 재정렬

> 핵심 한 줄: **지금 목표는 "AI가 헛소리 하는 것을 막는 것." RAG는 확률이라 잘못 걸면 틀린다 → 어렵게 가지 말고, 사용자가 인물 관계·설정을 직접 제시해 AI가 확실히 알게 + 연구해둔 RAG를 특화해 차별성으로. 데드라인 임박이니 현재 방향 고집.** (상세: [2026-06-16.md](2026-06-16.md))

### 강사님 피드백

**1. RAG/데이터 관리의 어려움**
- 우리 구조: 대화 전문 대신 **요약본을 계속 쌓고 최근 20턴만** 보며 RAG로 생성. 로직은 맞는 것 같으나 **오류가 계속 발생.**
- RAG는 **확률** — 잘못 걸면 잘못된다. 사람 말 인식→문장 생성은 결국 **데이터 관리 분야**(굉장히 어려운 파트).

**2. 어렵게 가지 마라 (핵심 조언)**
- AI는 **감정·태그**를 잘 못 잡는다(태그 다 안 주면 안 됨). 문맥은 되는데 감정·복선·연결선은 어렵다.
- 아마추어 작가가 처음 쓸 때 **인물 사이 관계는 본인이 정할 수 있으니** → 그걸 **AI에게 제시해 확실히 알게** 하라(감정을 AI가 추측하게 두지 말 것).

**3. 방향 특화 (데드라인 임박)**
- 연구·테스트를 많이 해뒀으니 **특화해서 차별성**으로. 기존 세계관을 LLM으로 가져와 사용자가 노는 방식(카피X·변형)은 가능성 있으나 시간상 보류.
- 강사님은 여전히 "AI가 전문을 쓰게 하는 게 낫지 않나" 생각 → 다만 **시간이 다 됐으니 현재 방향 고집.**

### 우리의 답변 (NodeVelture)

**1번(RAG 한계)에 대한 답 — "만능 생성"이 아니라 "추천·검수 층"에 RAG를 특화했다**
- RAG를 *생성*에 만능으로 붙이면 확률 오류가 그대로 노출된다. 그래서 **추천·검수 층**에 붙여 ROI를 살렸다 — 실측: 같은 검색을 넣어도 **생성 반영은 약함(+17%p)**, **추천 톤 변화는 또렷(±단조)**.
- 구조도 명확화: **증분 요약(5턴 단위 누적) + 최근 N턴 verbatim + 인앱 코사인 검색**(별도 벡터DB 없이 단편 규모에 충분).
- **검수 RAG를 화면에 노출**(모순 경고 배너 🔍)해 "검수가 돌고 있음"을 눈에 보이게 함 → 확률 오류를 사용자가 보고 판단. 수치: **장기기억 검색 top-1 100%**(방해정보 속) · **모순 탐지 합의셋 95%**(독립 교차검증).

**2번(어렵게 가지 마라 / 사용자가 관계 제시)에 대한 답 — 감정·관계를 AI가 추측하지 않게, 사용자가 명시 → AI는 따르기만**
- **캐릭터 행동 지시문(system_prompt)**: 인물 규칙을 사용자가 적으면 `[캐릭터 행동 지시문 — 반드시 따를 것]`으로 매 턴 주입 → AI가 추측 없이 따름.
- **호칭 규칙(address_rules)**: 인물이 다른 인물을 *어떻게 부르는지(관계)*를 사용자가 직접 지정 → AI가 그대로 사용(강사님 "관계는 본인이 정할 수 있다" 직격).
- **장르 가드**: AI가 장르 밖 요소를 추측해 끌려가지 않고, *"장르 밖 요소 감지 — 도입할까요?"* 사용자에게 물어 **통제권을 사용자에게**.
- → "AI가 감정·태그를 잘 못 잡는다"는 한계를 **사용자 명시 → AI는 실행**으로 우회.

**3번(방향 특화)에 대한 답 — 차별점을 3축으로 좁히고 수치로 증명, 컨셉 확정**
- 차별점을 **① 장기기억 ② 설정 검수 ③ 개인화(취향)** 로 좁힘. **문체 우위는 자기채점 거품이라 폐기**(독립심판 재측정) — 정직하게 한계 공개.
- "AI가 전문 쓰기" vs "사용자 참여" 중 **참여형(주인공 빙의 + 대화→소설 변환)으로 컨셉 확정**. 기존 세계관 변형은 시간상 보류, **현재 방향 특화에 집중**.

### 팀 결정사항 / 액션 아이템

- [ ] **전원** — GPT/다른 AI 플랫폼에 *"우리 서비스·규칙을 다 설명했을 때 알고리즘을 어떻게 설계할 것인가"* 물어보고 접근 비교
- [ ] **AI/백** — 감정을 AI가 추측하게 두지 말고 **사용자가 인물 관계·설정을 명시→AI가 확실히 인지**하는 쪽으로 단순화
- [x] **윤정** — 연구해둔 RAG(기억·검수)를 **차별점으로 특화·가시화** (검수 UI 노출·문맥 리액션·SSE 등 구현/배포)
- [ ] **전원** — 컨셉 확정: **같이 소설을 완성하는 플랫폼 / 타깃 = 아마추어 작가** ("아이디어는 있는데 쓸 줄 모르는 사람"). 공장식 생성 → 본인이 읽으며 수정

**개인 말투(Voice) 입력 방식**

- 말투 질문의 근거: **사람 성격이 드러나는 상황별 문장**(당황·서운함·미안함·거절·설렘)을 넣음.

  - 방향: **개인 휴대폰에서 웹/데이터를 긁어 → 비식별화 → 서버로 보내 분석** → 나만의 말투를 탑재한 소설.
  - **비식별화 필수.** 온디바이스 모델(젬마4/젬마 나노 등 휴대폰 동작 모델)도 검토 가능.

**피드백/추천 로직**
- 일단 **프롬프트로 작가 말투·컨셉 반영(API)**, **컨셉이 확실해지면 RAG 적용** 예정. 컨셉별 피드백 확인 후 프롬프트 수정.
- 작가 추천 대사에 **RAG 적용 시 사용자 특화 대사**가 나올지 → **실험 필요**(프롬프트에 변수 넣어 판단·제안하며 사용자화).
- **장르 추천부터 사용자 기반**으로 가면 좋음.

**AI 휴먼 / 연출**
- 사용자 입력에 따라 **이벤트 발생 시 작가 영상 재생 + 리액션**.
- **작가 답변의 첫 대사를 TTS로 낭독**.

**AI 철학 (중요)**
- "우리가 예측 못 하는 걸 AI가 — **패턴 추출·대화 이해**를 써먹으려 AI를 쓰는 것."
- **rule 기반은 한계가 분명** → **AI로 동적으로 만들면 계속 진화**.

**오탈자/맞춤법**
- **실시간 교정·마킹은 헤비하고 식상** → 지양.

- 예) 민준=잠입 형사 배경·받은 명령 / 지수=민준을 좋아하는 사실·친구 관계망 / 의문의 손님=사실은 형사 동료·작전 계획
- 발화 시 자기 RAG에서만 정보를 꺼냄

> ⚠️ **(2026-06-08 팀 결정) 이 "캐릭터별 비밀정보 분리" 항목은 채택하지 않음.**
> 강사님이 우리 서비스를 **추리극(AI 찾기 게임)으로 오해**한 맥락에서 나온 피드백.
> 빙의작가 서비스의 핵심 차별점으로는 부적합 → RAG는 아래 6/5 결정대로 **"세계관 일관성(장기 기억)"** 용도로 재정의.

### 3. 자체 모델 + 전후처리 (강사님 강조)
- **상용 API 지양**, 자연어는 **Qwen 2.5**가 가장 좋음
- 전처리(입력 정제·의도 파악) + 후처리(응답 품질 검증·페르소나 일관성 체크) 모델을 끼면 **성능 입증 가능**
- EXAONE은 비추(폐쇄망용)

### 4. 퍼포먼스 강화
- 첫 화면에서 **아바타가 캐릭터 대표 대사를 음성으로** → 진입 순간부터 몰입 (PERSO Avatar 활용처 명확화)

### 5. 서비스 레벨 확장 (프로덕트 사고)
- 동기부여 요소: 다른 유저 완성 현황, 진행률 게이지, 본인 스킨/캐릭터, 완성 보상
- 3주 안에 다 못 만들어도 **발표에 포함하면 점수 큼**

### 6. 삽화 생성 (멀티모달 확장)
- 대화 기반으로 결정적 장면에 삽화 자동 생성, 응답 품질이 낮을 때 삽화로 유도
- 무리면 발표 슬라이드에라도 포함

### 7. DB 이중 구조
- RDB(PostgreSQL): User/World/Character/Session/Novel (정형·관계형)
- NoSQL(MongoDB/Redis): Dialogue(대화 로그), RAG 벡터 임베딩, 캐릭터별 RAG 데이터
  > ※ 이후 6/5 스크럼에서 "PostgreSQL only로도 무방"으로 완화됨

### 8. 타겟 명확화
- 연령대 분류(아동 / 전문작가 / 취미 / 어르신), 페르소나가 타겟 연령대를 벗어나지 않게 제어
- 확장 아이디어: 일기·회고·자서전 초고 작성 → 어르신 타겟 자서전 시장

### 9. 디테일 명확화 (단편/장편)
- MVP: 단편 (대화 30~50턴 → 소설 한 편)
- 확장: 장편 (이어쓰기, 챕터 구분)

### 3주 안에 무조건 할 것 (우선순위)
1. ChatGPT 차별점 방어 논리 확정 (발표용)
2. RAG로 캐릭터별 정보 분리 (기술적 차별점)
3. 자체 모델(Qwen) + 전후처리 구조
4. 타겟 연령대 명확화 + 페르소나 제어
