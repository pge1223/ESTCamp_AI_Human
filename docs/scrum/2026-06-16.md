# 2026-06-16 스크럼 — RAG 한계 진단 & 방향 재정렬

> **핵심 한 줄:** 지금 목표는 *"AI가 헛소리 하는 것을 막는 것."*
> RAG는 확률이라 잘못 걸면 틀린다. 강사님 결론 = **어렵게 가지 말고, 사용자가 인물 관계·설정을 직접 제시 → AI가 확실히 알게** + **연구해둔 것을 특화해 차별성**으로. 데드라인 임박이니 **현재 방향 고집**.

---

## 1. 현재 구조 & 문제

- **데이터 흐름**: 대화 전문을 다 넣지 않는다. **요약본(summary)을 계속 쌓고**, 대화는 **최근 20턴만** 바라본다. 그 위에서 **RAG로 검색하며 계속 생성**해 나간다.
- 로직 자체는 맞는 것 같은데 **오류가 계속 생기는 상황.**
- **RAG는 확률** — 잘못 걸면 잘못된 결과가 나올 수 있다.
- 깨달음: *사람의 말을 인식해 문장을 생성*하는 건 결국 **데이터 관리 분야**다. → **굉장히 어려운 파트.**

## 2. 액션 — 알고리즘 설계 외부 검증

- GPT/다른 AI 플랫폼에 **"우리 서비스와 돌아가는 규칙을 모두 설명했을 때, 알고리즘을 어떻게 설계할 것인가"** 를 물어본다.
- **여러 AI 플랫폼에 설계를 묻고** 접근을 비교해본다.

## 3. 강사님 피드백

- AI는 사람의 **감정·태그**를 잘 못 잡는다 — **태그를 다 주지 않으면** 잘 안 된다. **문맥은 되는데 감정·복선·연결선**은 어렵다.
- **어렵게 가지 마라.** 아마추어 작가가 한 번도 안 써봤을 때, **등장인물 사이의 관계는 본인이 정할 수 있으니** → 그걸 **AI에게 제시해 확실히 알게** 하는 방향. (감정을 AI가 추측하게 두지 말고 사용자가 명시)
- **협업 방향**: 애초에 **여러 사람이 한 번에 보는** 식이었으면 — 다양성을 부여해 여러 사람이 협업 소설을 만드는 느낌이면 더 다양하게 나온다.
- 강사님은 여전히 **"AI가 전문(全文)을 쓰게 하는 게 낫지 않나"** 생각. → 다만 **시간이 다 됐으니 현재 방향을 고집**.
- 기존 세계관을 **LLM으로 가져와** 사용자가 그 안에서 노는 것(카피 요청이 아니라, "기존 걸 가져와서 이렇게 쓰고 싶다") — 가능성은 있으나 **시간상 지금 방향 유지**.
- **연구·테스트를 많이 해뒀으니 이걸 특화해서 차별성**을 두는 방향으로. 데드라인 임박 → **방향 잡아 특화.**

## 4. 결론 — 컨셉/방향 확정

- **같이 소설을 완성해 나가는 플랫폼**, 타깃 = **아마추어 작가**.
- 플랫폼이 **공장식으로 찍어내고**, 본인이 **읽으면서 수정 가능**하게.
- **"아이디어는 있는데 쓸 줄 모르겠는 사람"** 에게 도움이 되는 것 — 이게 우리 가치.
- 컨셉을 정확히 정하고, **남은 시간엔 현재 방향을 특화**한다.

---

### 한 줄 정리

> RAG·데이터관리는 어려운 분야라 오류가 남지만, **사용자가 관계·설정을 명시 → AI가 확실히 인지**하는 쪽으로 단순화하고, **연구해둔 RAG(기억·검수)를 차별점으로 특화**해 마감까지 현재 방향을 밀고 간다.
