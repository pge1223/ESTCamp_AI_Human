# NodeVelture RAG 성능 지표

> 측정일: 2026-06-09 · 엔진: Groq(llama-3.3-70b) + Gemini 임베딩(gemini-embedding-001)
> RAG 3종(기억·검수·문체)이 "켰을 때 vs 껐을 때" 실제로 차이를 내는지 측정한 결과.
> 재현 스크립트는 [backend/scripts/](../../backend/scripts/)의 `rag_demo` · `consistency_demo` · `style_demo`.

## RAG가 쓰이는 3곳

| 구분 | 기능 | 모듈 | 한 줄 |
|------|------|------|-------|
| ① 기억 | 세계관 일관성 RAG (F-CH-10) | `services/memory.py` | 오래된 대화를 의미검색해 프롬프트에 주입 → 안 까먹음 |
| ② 검수 | 설정 일관성 검수 (F-QC-01) | `services/consistency.py` | 새 응답을 확립된 설정·기억과 대조해 모순 탐지 |
| ③ 문체 | 문체 RAG (F-NV-08) | `services/style.py` | 작가 문체 예시를 장면별 검색해 소설 변환 few-shot 주입 |

공통 인프라: Gemini 임베딩 + 코사인 유사도 top-K (별도 벡터 DB 없이 in-app, 단편 규모에 충분).

---

## ① 기억(Memory) — "6턴 전 설정을 기억하는가"

**방법** (`python -m scripts.rag_demo`): 1턴에 비밀("민준은 잠입 형사")을 심고, 잡담 5턴으로 밀어낸 뒤 6턴째에 "민준의 정체?"를 물어 RAG off/on 비교.

| 조건 | 떠올린 기억 | 결과 |
|------|------------|------|
| ❌ RAG OFF (최근 대화만) | (없음) | 비밀을 못 떠올림 |
| ✅ RAG ON (의미 검색) | "민준은 사실 잠입 수사 중인 형사다…" (6턴 전) | **정확히 회상** |

→ **차이 압도적 (OFF=0 / ON=정확 회상).** ChatGPT 대비 핵심 차별점의 직접 증거.

---

## ② 검수(Consistency) — "설정 모순을 잡아내는가"

**방법** (`python -m scripts.consistency_demo`): 확립된 설정("민준=잠입 형사")에 대해 모순/정상 문장을 검수.

| 검수 대상 | 결과 |
|-----------|------|
| 모순: "민준은 병원에서 일하는 외과 의사였다" | 🚨 **모순 발견** — 설정: 잠입 형사 / 충돌: 외과 의사 `[high]` |
| 정상: "민준은 주문서를 받아들고 고개를 끄덕였다" | ✅ 일관성 OK |

→ 모순은 정확히 탐지, 정상은 통과. "독자 입장 검수 어시스턴트"(강사님 6/9)의 실동작.

---

## ③ 문체(Style) — "작가 문체를 더 살리는가"

**방법** (`python -m scripts.style_demo`): 같은 장면을 한여름 작가로 소설화, 문체 few-shot off/on을 **각 3회 생성·채점 평균**(LLM 변동성 보정). 채점은 `evaluate.py`(LLM-judge, 4축 1~5점).

| 조건 | 작가 문체 뚜렷함 | 합계(20점) |
|------|:---:|:---:|
| ❌ 문체 RAG OFF (추상 규칙만) | 4.33 | 17.33 |
| ✅ 문체 RAG ON (예시 few-shot) | **4.67** | **18.33** |
| **차이** | **+0.34** | **+1.00** |

→ 양(+)의 효과. 단 격차가 작음 — 페르소나 추상 규칙(novel_style)이 이미 문체를 상당히 잡아서 few-shot의 마진이 작기 때문. **반드시 다회 평균으로 볼 것**(단일 회차는 변동으로 OFF가 이길 수 있음).

## 종합

| RAG | 측정 | OFF | ON | 차이 |
|-----|------|-----|-----|------|
| ① 기억 | 6턴 전 비밀 회상 | 회상 실패 | 정확 회상 | **압도적** |
| ② 검수 | 모순 탐지 | — | 모순/정상 정확 판별 | **명확** |
| ③ 문체 | 문체 점수(3회 평균) | 17.33 | 18.33 | +1.00 |

## 한계 & 개선 방향 (정직하게)
- **Groq 변동성**: 단일 회차 점수는 흔들림 → 측정은 다회 평균 권장.
- **언어 누수**: Groq llama가 한자·일본어를 섞음 → 점수·가독성 저하. **GPT 전환 시 해소 + 격차 확대 예상**.
- **문체 효과가 작은 이유**: 추상 규칙이 강해 few-shot 마진이 작음 → 샘플 풀 확대([data/style_samples.json](../../backend/app/data/style_samples.json), 현재 작가당 12개)와 GPT로 개선.
- **근거 리포트(F-EV-06)**: 짧은 시나리오는 RAG '기억' 강점이 안 드러남 → **긴 시나리오 + 다회 평균 + GPT**로 신뢰값 산출 필요. (`scripts/evidence_report.py`)

## 재현 방법
```bash
# backend 폴더, conda nodevelture 환경, DB(5433)·LLM 키 필요

python -m scripts.consistency_demo  # ② 검수 (모순/정상)
python -m scripts.style_demo        # ③ 문체 (off/on 3회 평균)
python -m scripts.evidence_report   # 맨손 vs 우리 종합 비교
```
