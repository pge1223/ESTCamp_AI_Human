## 3. 타깃 사용자

### 주요 타깃
- 웹소설 독자 중 직접 써보고 싶지만 막막한 사람
- 글쓰기 지망생 중 첫 화를 완성 못 한 사람
- 세계관·캐릭터 설정은 잘 하는데 실제 집필이 어려운 사람
- 크랙 같은 AI 채팅 서비스를 즐기지만 결과물이 남지 않아 아쉬운 사람

### 해결하는 문제

| 문제 | 기존 해결책 | Nodevelture |
|------|------------|-------------|
| 첫 문장에서 막힘 | ChatGPT에 써달라고 함 | AI와 함께 세계관 뼈대부터 잡고 시작 |
| AI가 써준 글 같은 느낌 | 없음 | 내가 직접 대화에 참여해서 만든 이야기 |
| 재밌게 놀았는데 결과물이 없음 | 크랙 (대화 기록만 남음) | 대화 로그가 소설 초안으로 자동 변환 |
| 혼자 쓰면 이야기가 안 풀림 | 비싼 글쓰기 코칭 | AI 등장인물들이 실시간으로 반응하며 이야기 전개 |

## 4. 핵심 사용 시나리오 3가지

### 시나리오 1 — 세계관 설정: AI와 함께 뼈대 잡기

**상황**: 로맨스 판타지를 쓰고 싶은데 어디서 시작해야 할지 모르는 사용자

**흐름**:
1. "오늘 어떤 세계로 떠나고 싶으세요?" → 한 문장 입력
2. "재벌 2세한테 고백받고 싶어"
3. AI(협업자 페르소나)가 세계관·등장인물·배경 자동 제안
4. 사용자가 수정·확정
5. 조연 3명 성격·관계 설정 완료

> 진입 장벽 없이 5분 안에 세계관 완성

---

### 시나리오 2 — 대화형 창작: 내가 등장인물이 되어 체험

**상황**: 세계관 설정 완료 후 본격 이야기 시작

**흐름**:
```
[상황]
편의점 알바생 민준이 계산대에 서 있다.

[나의 입력]
"저 여기 자주 오는데 저 기억하세요?"

[민준 반응 - 차가운 타입]
"...글쎄요." (시선을 계산대로 내리깔며)
"2,500원입니다."

[동료 알바 지수 반응]
(작게 웃으며 뒤돌아섬)
```

> AI가 조연 여러 명을 동시에 각자 페르소나로 반응
> 내 선택마다 이야기가 달라짐

---

### 시나리오 3 — 소설 변환: 놀았더니 초안이 완성

**상황**: 대화 30턴 쌓인 후 소설 변환 요청

**변환 예시**:
```
[대화 로그]
나: "저 여기 자주 오는데 저 기억하세요?"
민준: "...글쎄요. 2,500원입니다."

↓ 소설 초안으로 변환 ↓

나는 용기를 내어 말을 걸었다.
"저 여기 자주 오는데, 혹시 기억하세요?"
민준은 잠시 나를 바라보다 시선을 내렸다.
"...글쎄요."
짧은 대답과 함께 그는 계산대 화면만 바라봤다.
"2,500원입니다."
```

> 사용자는 그냥 재밌게 놀았는데 끝나고 보니 소설 초안이 완성

## 6. 서비스 구조 및 페르소나 설계

### 전체 흐름
```
1단계 - 세계관 설정
AI(협업자)와 함께 뼈대 잡기
장르 / 배경 / 등장인물 3~5명 설정
↓
2단계 - 대화형 창작
사용자 = 주인공 / AI = 조연들
내 대사·행동 입력 → 조연들이 각자 페르소나로 반응
선택에 따라 이야기 분기
↓
3단계 - 소설 변환
대화 로그 → 소설 문체로 자동 변환
저장 / 공유 / 다른 선택으로 다시 하기
```

### 페르소나 구조

| 페르소나 | 담당 | 역할 |
|---------|------|------|
| 협업자 (작가 AI) | 1단계 세계관 설계 | 뼈대 제안, 막힐 때 방향 조언 |
| 등장인물 A | 2단계 대화 내내 | 설정된 성격·말투로 반응 |
| 등장인물 B | 2단계 대화 내내 | 설정된 성격·말투로 반응 |
| 등장인물 C | 2단계 대화 내내 | 설정된 성격·말투로 반응 |

### AI 페르소나 구현 방식
```
[방법 1 - 시스템 프롬프트 통합 (기본)]
하나의 API 호출로 여러 캐릭터 반응 동시 생성
→ PERSO API 할당량 절감, 속도 빠름

[방법 2 - 캐릭터별 개별 호출 (중요 장면)]
캐릭터마다 별도 프롬프트로 개별 호출
→ 페르소나 일관성 높음, 비용 증가

[하이브리드 - 권장]
평소: 방법 1 / 감정 분기점: 방법 2
```

## 7. 결과물 형태와 모달리티

### 결과물 형태: 웹앱 (PC / 모바일 크로스)
- PC: 세계관 설정 + 본격 창작에 최적
- 모바일: 언제든 이어서 체험 가능
- PWA로 크로스 플랫폼 대응

### UI 구성
- 왼쪽: 소설 편집 영역 (대화 + 서술 혼합)
- 오른쪽: 등장인물 채팅 영역 (캐릭터 아바타 + 대화)
- 상단: 세계관 정보 / 등장인물 감정 상태
- 하단: 소설 변환 버튼

### 모달리티

| 모달리티 | 적용 | 구현 방법 |
|---------|------|----------|
| 텍스트 (기본) | 필수 | 웹 텍스트 에디터 |
| PERSO Avatar | 권장 | 등장인물 캐릭터 아바타 |
| 음성 출력 (TTS) | 선택 | PERSO API TTS |
| 음성 입력 (STT) | 선택 | Web Speech API |

## 8. 응답 엔진 선택 및 기술 스택

### 응답 엔진 전략

| 레이어 | 역할 | 기술 | 비중 |
|--------|------|------|------|
| PERSO API (1순위) | 메인 페르소나 응답 생성 | PERSO LLM API | 시연·평가 70% |
| 파인튜닝 모델 (자체) | 캐릭터별 문체 특화 | 모방학습 기반 경량 모델 | 개발·실험 주력 |
| 대체 LLM (폴백) | 할당량 초과 시 | GPT-4o-mini / Claude Haiku | 비상용 30% |
| LLM-as-Judge | 페르소나 일관성 자동 평가 | 별도 평가 전용 모델 | 평가 파이프라인 |

### 데이터
- 공유마당 (저작권 만료 한국 소설)
- Project Gutenberg (해외 고전 소설)
- AIHub (한국어 소설 말뭉치)
- 장르별 few-shot 예시 직접 작성

### 기술 스택

| 영역 | 기술 | 이유 |
|------|------|------|
| 프론트엔드 | React + TypeScript | 스트리밍 처리, 컴포넌트 재사용 |

| 배포 | Render / Railway | 3주 내 실제 배포 목표 |
| 버전관리 | GitHub + GitHub Projects | 브랜치 전략, 이슈 트래킹 |

## 9. 평가 기준

### 정량 지표

| 지표 | 정의 | 측정 방법 | 목표 |
|------|------|----------|------|
| 페르소나 일관성 | 캐릭터 톤이 흔들리지 않는가 | LLM-as-Judge 5점 척도 | 평균 4.0 이상 |
| 캐릭터 구분도 | 조연들 반응이 얼마나 다른가 | 코사인 유사도 역산 | 캐릭터 간 유사도 < 0.6 |
| 소설 변환 품질 | 대화 → 소설 자연스러움 | 휴먼 평가 5점 | 평균 4.0 이상 |
| 응답 지연 | 사용자 체감 속도 | P95 latency | < 5,000ms |
| 캐시 히트율 | 중복 호출 절감 | cache_hit / total | > 30% |

### MVP 범위
- 장르 3개 (로판 / 추리 / 현대)
- 조연 3명 (페르소나 깊게)
- 고정 시나리오 1개 + 자유 입력
- 소설 변환 + 저장·공유
- 엔딩 2개 (해피 / 배드)

### 리스크 관리

| 리스크 | 대응 |
|--------|------|
| PERSO API 할당량 조기 소진 | 1주차부터 자체 모델로 개발, 엔진 스위칭 구조 필수 |
| 페르소나 일관성 부족 | 시스템 프롬프트 강화 + few-shot 10개 이상 |
| 소설 변환 품질 낮음 | 변환 전용 프롬프트 별도 설계 |
| 3주 내 배포 실패 | 2주차 말 통합 테스트 게이트 설정 |
