# 1팀 NodeVelture 기획서 (현행판)

> AI휴먼 캠프 4기 · 2차 프로젝트 (2026.06.02 ~ 06.19) · 팀 NodeVelture(woawoal)
> ※ 본 문서는 초기 기획안이 아니라 **마감 시점의 실제 구현·실측을 반영한 현행 기획서**다.

---

## 1. 서비스 개요

- **한 줄 정의**: 소설을 쓰고 싶지만 막막한 사람에게, **AI 작가와 놀듯 대화하면 단편 소설이 완성**되는 협업 창작 파트너.
- **타깃**: *"아이디어는 있는데 쓸 줄 모르는"* **아마추어 창작자**(웹소설 친화 2030).
- **핵심 가치**: '쓰는' 게 아니라 '대화하는' 것 → 대화가 끝나면 **내 단편 한 편**이 남는다.

**3단계 핵심 흐름**

```
① 세계관 설정        ② 대화형 창작                 ③ 소설 변환
작가 선택 + 장르·    사용자=주인공 / AI=나레이션·    대화 로그 →
배경·등장인물 설계 ─▶ 조연 (기억·검수 RAG로 일관성) ─▶ 작가 문체의 단편소설 + 삽화
```

## 3. 문제 정의 & 차별점

| 사용자 문제 | NodeVelture 해법 |
|---|---|
| 빈 화면 공포 — 첫 문장이 안 써짐 | 작가 선택 + 세계관 폼 → AI가 **첫 장면을 던져줌** |
| 설정 붕괴 — 길어지면 앞 설정을 까먹음 | **① 기억 RAG** — 오래된 설정을 의미검색해 재주입 |
| 모순 통과 — "아까 형사라며?"를 못 잡음 | **② 검수 RAG** — 새 문장 ↔ 설정 모순 탐지 (화면 노출) |
| 내 취향이 안 남음 | **③ 개인화 RAG** — 저장 문장 기반 추천 |
| 혼자라 안 이어짐 | 작가 리액션(음성)·개인화로 *끝까지 같이* |

> **핵심 차별**: 범용 LLM(ChatGPT)이 *못/안 하는* **긴 맥락 기억 · 설정 검수 · 개인화**를 하고, **독립 심판 수치로 증명** + **대화→소설 변환**으로 결과를 남긴다.

## 4. AI 작가 페르소나 (4인)

| 작가 | 장르 | 말투·문체 | 테마 |
|------|------|-----------|------|
| **백야** | 호러·미스터리 | 건조·단절적, 여백 | 다크 |
| **차로운** | 본격 추리 | 분석적·논리, 복선 | 다크 |
| **한여름** | 로맨스 | 따뜻·감각 묘사 | 라이트 |
| **김도현** | 일상·에세이 | 담담·절제 | 라이트 |

- 구현: **시스템 프롬프트 + 문체 예시(few-shot)** + 작가별 화면 테마·BGM·음성(TTS).
- 작가를 고르면 말투·장르·문체·화면 톤이 통째로 바뀐다.

## 5. 핵심 기능 (현재 구현)

**창작 흐름**
- **세계관 생성/수정** — 제목·장르·배경·규칙 + 등장인물(성격·**행동 지시문**·**호칭 규칙**). 한 번 만든 세계관도 **수정 가능**(soft/hard 가드).
- **대화형 창작** — 사용자=주인공 빙의. **@등장인물**로 조연 빙의(그 인물 대사 직접 입력). 화자 고정, **SSE 토큰 스트리밍**(첫 토큰 즉시).

**AI 코어 — RAG 3종**
- ① **장기기억 검색**(인앱 코사인) — 방해정보 속에서도 과거 설정 회상
- ② **설정 검수** — 새 문장↔설정 모순 탐지 → **화면 경고 배너**(🔍 토글)
- ③ **개인화 추천(취향저격)** — 저장 문장 의미검색 → 추천 톤에 반영

**연출·멀티모달**
- **작가 리액션** — 입력+답변 문맥으로 감정 잡아 작가 말투 한마디 + **음성(ElevenLabs)**
- **삽화 생성** — 장면 → 그림(Vertex Gemini Image), DB 저장
- **작가별 BGM** + **환경설정**(BGM·로딩영상 소리·리액션 음성 ON/OFF·볼륨)

**품질·안전**
- **맞춤법 교정** + 개인 **오답노트**(자주 틀리는 것 예측 경고)
- **장르 가드** — 장르 밖 요소 감지 → "도입할까요?" 사용자에게 선택권
- **안전성** — 욕설·위험·비윤리 입력에 작가 톤 유지하며 수위 조절·우회

**완성·보관**
- **소설 변환** — 대화 로그 → 작가 문체 단편 → 읽기·삽화
- **마이페이지(서재)** — 대시보드·취향 프로필·갤러리·오답노트·환경설정

## 6. 시스템 구조 & 기술 스택

```
[클라이언트] React + Vite (반응형) — Vercel
   │ REST + SSE(토큰 스트리밍)        └ Vercel 서버리스 함수 /api/tts → ElevenLabs(키 격리)
[백엔드] FastAPI — GCP Cloud Run (상시 HTTPS, min-instances=1)
   ├─ Neon PostgreSQL (대화·소설·삽화·비용 로그)
   ├─ Upstash Redis (히스토리·요약·세션 상태)
   └─ Vertex AI (Gemini 2.5 Flash-lite 텍스트 · Gemini Image 삽화 · 임베딩) — 폴백 Groq·OpenAI
[인증] Neon Auth (better-auth)
```

| 레이어 | 기술 |
|---|---|
| 프론트 | React + Vite · Vercel |
| 백엔드 | FastAPI(async) · GCP Cloud Run · REST + SSE |
| DB / 캐시 | Neon PostgreSQL / Upstash Redis(NoSQL) |
| 응답엔진 | Vertex AI Gemini 2.5 Flash-lite (ADC 키리스) · 폴백 체인 Gemini→Groq→OpenAI |
| 멀티모달 | Vertex Gemini Image(삽화) · ElevenLabs(TTS, Vercel 프록시) · 작가별 BGM |
| 인증·보안 | Neon Auth · Google Secret Manager · 키는 서버사이드 격리 |

- **응답엔진 전략**: 환경변수(`LLM_PROVIDER`·`USE_VERTEX`)로 **언제든 스위치/폴백** → 한 엔진이 막혀도 시연 안 끊김.
- **데이터**: RDB(정형: 세계관·세션·소설·삽화) + Redis(캐시·요약·세션). 단편 규모라 별도 벡터DB 없이 **인앱 코사인**.

## 9. 정직한 한계 & 향후

- **TTFB**: 완성-응답 기준 5.9s. SSE 토큰 스트리밍으로 첫 토큰은 빠르나, 근본 개선은 Neon 리전 정렬.
- **완료율 65.2%**: 데모/테스트 미완주 영향. 정상 완주 흐름 강화 필요.
- **MOS 미측정**: 자동지표↔사람 느낌 교차검증은 발표 전 1회 수집 예정.
- **프롬프트의 한계**: 모델의 입력 충실 편향은 프롬프트만으로 안 꺾여, 상류 차단(장르 가드)·구조적 개입으로 대응.
- **향후**: 자동 배포(CI/CD), 예측형 추천, 세계관 버전닝, (확장) 영상 아바타.

> **한 줄 결론**: NodeVelture는 *"놀듯 대화 → 진짜 내 소설"* 을, **기억·검수·개인화**라는 GPT가 구조적으로 약한 지점으로 차별화하고, 그 차별을 **수치로 정직하게** 증명한다.
