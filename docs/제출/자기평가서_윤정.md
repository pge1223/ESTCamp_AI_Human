## 담당 역할
팀장 / 백엔드 코어 · 멀티모달 통합 · 배포 · 정량 평가

## 한 일 (핵심)

- **백엔드 코어** — FastAPI 채팅/세션/소설 파이프라인, 작가 페르소나 시스템, **RAG 3종**(장기 기억·설정 검수·문체 few-shot), 맞춤법 교정(F-QC-02)·개인 오답노트.
- **개인화 RAG(취향저격)** — 미사용 자산이던 `SavedSentence`(사용자 저장 문장)를 의미검색해 추천 근거화. **통제 실험으로 인과 검증**(동일 세계관·장면·작가, 저장 톤만 다름 → 추천 톤 DARK 4.0 < NONE 5.9 < WARM 6.9, 완벽 단조).
- **멀티모달** — 삽화 엔진 **fal.ai → Vertex Gemini Image 전환**(결제·차단 이슈 우회) + DB 영속, **작가 음성 리액션**(ElevenLabs)을 **Vercel 서버리스 프록시**로 구현해 Cloud Run 키 제약 우회.

- **세계관 수정 + 검수 가시화** — 한 번 지정하면 못 고치던 세계관을 **수정 가능**하게(soft/hard 가드·기존 인물 이름잠금) + **world_context를 서버 권위로 통일**해 수정이 다음 대화에 즉시 반영. **설정 검수 RAG를 화면에 노출**(모순 경고 배너 + 🔍 토글) — '검수가 돌고 있음'을 눈으로 보이게 함(강사 피드백 *"구조가 안 보인다"* 직격).
- **성능/UX** — 마이페이지 대시보드 쿼리 병렬화(6.9s→~2s), **TTFB 개선**(생성 후 DB저장·요약을 응답 뒤로 deferral + Cloud Run min-instances=1 → **p50 8.7s→5.9s·p95 16.5s→6.8s**) + **SSE 토큰 스트리밍**(narration 생성 즉시 delta로 흘려 첫 토큰 체감 단축 — **백/프 배포 완료**, dev 머지 + Cloud Run 00048-289), 세계관→채팅 전환 병렬화, alert→토스트 등.
- **배포·운영** — Cloud Run·Vercel 배포 트러블슈팅, 환경변수/시크릿 함정 체크리스트화(표준 배포 명령의 `OPENAI_API_KEY` 누락 → 시크릿 삭제 위험 발견·문서화), 서비스 전체 점검(e2e + 코드 감사).
- **팀장 — PR 통합 게이트키핑** — 전 PR(#99~#107) 머지 가능성 점검(CI·충돌·신선도·마이그레이션)·충돌 해결·팀원 CI 핫픽스. **반복 회귀 방어**(말투 추천 💡 시스템이 여러 번 삭제되어 매번 복구), **squash→merge-commit 전환**으로 고스트 커밋 정리, 머지 워크플로(전원 1승인) 정립.

## 아쉬운 점 (약점 → 근거 → 개선 계획)
- **휴먼 평가(MOS) 미실시** — 모든 품질 지표를 자동/LLM-judge로만 측정. 자동지표가 사람 느낌과 같은 방향인지 교차검증이 0건. → *개선:* 평가자 5명 × 샘플 10개의 MOS 폼을 발표 전 1회 수집(인프라 불필요, 일정만 확보).
- **TTFB 여전히 목표 초과(5.9s > 1.5s)** — deferral·min-instances로 p95는 16.5→6.8s로 줄였으나, 응답을 완성한 뒤 1회 전송하는 구조라 한계. → *대응:* SSE **토큰 스트리밍**(narration delta 즉시 전송)을 **백/프 배포 완료**(dev 머지 + Cloud Run 00048-289) — 첫 토큰 기준 체감 TTFB는 ~1–2s로 내려감. 남은 과제는 Neon 리전 정렬.
- **프롬프트만으로 못 고치는 한계를 실측으로 확인** — 현실 세계관에 판타지 입력(엣지 #29)이 들어오면 소설 변환 품질 저하(1/5). **세계관 가드 프롬프트를 2회 시도했으나 변환 모델의 "입력 충실 렌더링" 편향으로 무효** 확인 → 토큰만 늘어 되돌림. *개선:* 근본 해결은 (a) 상류 입력 단계 차단(피드백 가드 적용 완료) 또는 (b) 구조적 전처리. 현재는 채팅 경로의 장르 감지로 선차단되어 실사용 영향은 제한적.
- **테스트셋 규모가 작음** — 균형 40문항(엣지 8·안전 4)은 방향 근거이지 통계적 벤치마크는 아님. → *개선:* 카테고리당 n 확대 + 반복 측정.
- **자동 회귀 테스트 부족** — 출시 점검을 수동 e2e + 평가 스크립트로 메움(CI 미구축). → *개선:* 핵심 엔드포인트 스모크 테스트를 CI에 연결.

## 배운 점
- 클라우드 배포의 현실적 제약(데이터센터 IP 차단·키 정책)과 **벤더 우회 설계**(서버리스 프록시).
- 멀티 LLM **폴백 체인**과 RAG의 품질↔비용 트레이드오프를 데이터로 보는 법.
- **정직한 평가 설계** — 자기채점(같은 모델이 채점)은 거품을 만든다. **독립 심판·출제 편향 제거(교차 라벨링)·통제 실험(인과 ablation)**으로 재면 수치가 내려가도 그게 방어 가능한 진짜 값. "100%"보다 한계를 함께 공개하는 게 신뢰를 높인다.
- **프롬프트의 한계** — 모델의 강한 편향(입력 충실 렌더링, 인물 생성)은 프롬프트 지시만으로 안 꺾이는 경우가 있다. 그때는 구조적 개입(컨텍스트 제거)이나 상류 차단이 답.
- **RAG는 '생성'보다 '추천/검수' 층에서 효과가 크다** — 같은 검색을 넣어도 생성 단계 반영은 약하고(+17%p), 추천 톤 변화는 또렷(±단조). 어디에 RAG를 붙이느냐가 ROI를 가른다.
