# 사용자 시나리오 (확정)

> 확정: 2026-06-08 · 이 문서가 사용 시나리오의 기준(source of truth).
> 기존 [planning/NodeVelture.md](planning/NodeVelture.md) §4의 모호했던 시나리오를 대체한다.
> 관련: [기능정의서](기능정의서.md), [문체모델 연동 설계](문체모델_연동_설계.md)

## 핵심 플로우

```
1) 작가 선택 (4명 중 1명)
2) 세계관 폼 작성 (제목·요약·배경·규칙 + 등장인물) → 채팅 페이지로
3) AI가 세계관 정보를 토대로 "상황(오프닝)" 부여
4) 사용자가 주인공이 되어 대사 입력 (왼쪽 채팅 공간)
5) 작가 AI가 등장인물을 등장시키거나 상황을 설명하는 식으로 응답
   → 대사/나레이션 구분은 입력을 보고 AI가 알아서 (프롬프트로 처리)
6) 추가하고 싶은 설정은 오른쪽 "작가 메모"에 입력 → 즉시 세계관에 반영
   (4~6을 반복하며 이야기 진행)

  ↓ 「채팅 종료」 버튼

7) 누적된 대화를 토대로 단편 소설 도출 (선택한 작가의 문체)
   → 사용자가 읽으면서 수정
```

## 단계별 정의

### 1) 작가 선택
- 메인 화면에서 작가 4명 중 선택: 백야(호러·미스터리) / 차로운(추리) / 한여름(로맨스) / 김도현(일상·에세이)
- 선택한 작가가 **그 세션의 문체·장르 정체성**을 결정한다.

### 2) 세계관 설정 (폼 작성)
- 세계관 페이지에서 **칸에 맞춰 폼으로** 작성한다 (대화형 아님). 실제 폼 필드:
  - 세계관: **제목 / 요약 설명 / 시대·공간 배경 / 특별 규칙** (장르는 선택한 작가 장르로 자동)
  - 등장인물(1~N): **이름 / 성격 / 역할 / AI 캐릭터 지시문**
- 작성 완료 → 세계관 + 등장인물이 DB에 저장되고 채팅 페이지로 이동.

### 3) AI의 상황 부여 (오프닝)
- 채팅 진입 시 AI가 세계관 정보를 토대로 첫 상황을 제시한다.
- 예) "비 오는 날, 너는 오래된 카페 구석에서 누군가를 기다리고 있다."

### 4) 사용자 = 주인공, 대사 입력
- 사용자는 1인칭 주인공으로서 대사·행동을 입력한다.
- 예) "기억하세요? 저 여기 자주 왔는데."
- **기본은 "주인공"으로 입력**하되, **`@등장인물` 멘션으로 다른 등장인물의 시점·대사로도 입력 가능**(작가AI가 그 인물 서사로 전개) — F-CH-18로 구현(2026-06-13). 작가/나레이터로 직접 쓰는 모드는 두지 않음(작가 역할은 메모로).

### 5) AI 응답 — 등장인물 또는 작가 나레이션 (AI가 자동 구분)
- **등장인물 응답**: 장면에 조연이 있고 사용자가 말을 걸면, 그 조연이 대사·행동으로 반응.
- **작가 나레이션 응답**: 상황 묘사가 필요하면 작가가 지문(나레이션)으로 장면을 이어간다.
- **핵심**: 사용자가 모드를 고르지 않는다. AI가 입력을 보고 알아서 둘 중 하나(또는 혼합)로 응답.
- 응답은 **대사 + 지문**을 함께 사용해 몰입감을 준다.

### 6) 메모 = 추가 상황/설정 주입 ("작가" 기능)
- 오른쪽 메모 칸에 추가하고 싶은 설정을 적으면, AI에게 **추가 상황으로 주입**된다.
- 예) "사실 민준은 주인공의 첫사랑이다", "이 카페는 곧 문을 닫는다"
- **메모는 적으면 즉시(바로 다음 응답부터) 반영된다.** (저장 버튼 대기 없음)
- 한 번 주입된 설정은 이후 응답에도 계속 유지된다 (→ 세계관 일관성 / 장기 기억).
- 즉 사용자는 *주인공으로 연기(채팅)* 하면서 동시에 *작가로 세계를 손본다(메모)*.

### 7) 소설 변환 (「채팅 종료」 버튼)
- 사용자가 **「채팅 종료」 버튼**을 누르면 한 챕터(세션)가 끝난다. (MVP는 버튼 방식 — AI 자동 종료 판단은 추후)
- 누적 대화 로그를 **선택한 작가의 문체로** 단편 소설 초안으로 변환한다.
- 사용자는 결과를 읽으면서 수정할 수 있다. 읽기 화면에서 **장면 삽화 생성**(Vertex Gemini 2.5 Flash Image)·내보내기(.txt)도 가능.
- (문체 모델 후처리는 [문체모델 연동 설계](문체모델_연동_설계.md) 참고)

### 8) 맞춤법 교정 · 오답노트 (F-QC-02 — 반응형→예측형 개인 맞춤 루프)
글쓰기(4번 입력) 중 사용자 문장을 교정하는 기능. **틀리면 고쳐주는 것(반응형)** 에서 **틀리기 전에 미리 짚어주고 내가 관리(예측형)** 로 이어지는 개인 맞춤 루프다.

**구성**
- **판정**: 네이버 맞춤법기로 원문↔교정문 **단어단위 diff** → 오류쌍 추출. **LLM은 판정하지 않는다(환각 차단).**
- **고유명사 보호**: 등장인물·세계관 제목 + LLM 1회 추출 용어집 + 「넘기기」 누적 → 창작 고유명사는 오탐에서 제외.
- **문체 예외**: `ㅋㅋ`·늘임(`~~`)·자모는 교정 대상 아님.
- **작가 톤 메모**: 교정을 작가 말투로 "여백 메모" 한 줄(표현만, 판정 X). **사용자를 놀리거나 비꼬지 않는다(가드).**
- **오답노트(error_profile)**: 사용자별 누적(`틀린표기→교정·유형·횟수·시각`). 2회 이상 = 자주 틀림(frequent).
- **능동 경고(warmup)**: 글쓰기 진입 시 자주 틀리는 것을 미리 카드로 보여줌.
- **삭제**: 마이페이지 오답노트에서 항목별 ✕ 삭제.

**원칙**: ① **자동 수정하지 않는다** — 제안만, 「적용」/「넘기기」는 사용자가 선택. ② 교정은 **세션 소유자 계정**(`session.user_id`)에 누적된다.

**흐름**
```
① 채팅/에디터 진입 → 💡 능동 경고: "자주 놓치는 것 — 너가→네가, 또 다시→또다시"
② 문장 작성 → 교정 요청 → (네이버 판정→diff→오류쌍→작가 메모→오답노트 누적)
③ 결과 표시:  접근해야할까 → 접근해야 할까 [띄어쓰기]  + 작가 메모("…이게 맞지.")
④ 「적용」(반영) / 「넘기기」(이건 맞음 → 용어집 등록, 다음부터 제외)
⑤ 반복 실수 → frequent("또 나왔어요")
⑥ 마이페이지 > 오답노트: 상위 10개 · 많이틀린순/최신순 · ✕ 삭제
⑦ 다음 글쓰기 진입 → ①로 리마인드 (루프 완성)
```

**차별점**: ChatGPT엔 없는 **영속적 개인 오답 기억** — 쓸수록 내 약점을 알고 미리 짚어준다.

## 구현 매핑 (참고)

| 시나리오 | 구현 위치 |
|----------|-----------|
| 1) 작가 선택 | `GET /authors`, main 페이지 |
| 2) 세계관 폼 작성 | `/worlds`, `/worlds/{id}/characters`, worldview 페이지 (폼) |
| 3) 상황 부여 | 채팅 진입 시 AI 오프닝 (구현 필요) |
| 4~5) 대화·응답 | `POST /chats/{id}/messages` → `GET /chats/{id}/stream` |
| 5) 대사/나레이션 자동 구분 | 작가 프롬프트가 "입력에 따라 대사·나레이션·인물 등장"을 처리 ([personas.py](../backend/app/core/personas.py)) |
| 6) 메모 즉시 주입 | 메모 내용 → 세션 컨텍스트에 누적 주입(즉시 반영) ([chats.py](../backend/app/api/v1/endpoints/chats.py) `build_prompt`) — 연결 필요 |
| 7) 채팅 종료 → 소설 변환 | 「채팅 종료」 → `PATCH /sessions/{id}/complete` → `POST /sessions/{id}/novel/generate` (작가 문체) |
| 8) 맞춤법 교정 | `POST /chats/{id}/proofread` (판정+작가 메모), 용어집 `GET/POST/DELETE /chats/{id}/glossary` ([proofread.py](../backend/app/api/v1/endpoints/proofread.py)) |
| 8) 능동 경고 | `GET /chats/{id}/error-warmup` (자주 틀리는 것 미리 보기) |
| 8) 오답노트·삭제 | `GET /users/{id}/error-notebook`, `DELETE /users/{id}/error-notebook` (마이페이지) |

## 이 시나리오로 정리된 핵심 결정

- **세계관 = 폼 작성** — 대화형이 아니라 칸에 맞춰 입력 (구현 비용↓, 진도↑).
- **사용자 입력 = 기본 주인공 + `@등장인물`로 다른 인물 연기**(F-CH-18, 06-13 구현) — 작가/나레이터로 직접 쓰는 모드는 두지 않음.
- **채팅 모드 토글 없음** — 작가 AI가 대사/나레이션/인물 등장을 입력 보고 자동 처리 (5단계).
- **작가의 역할** = ① 세계관 설계 길잡이(1·2단계) + ② 채팅 응답 주체 + ③ 소설 변환 문체(7단계).
- **메모 = 작가 기능** — 별도 "작가모드" 채팅이 아니라, 설정을 세션 컨텍스트에 즉시 주입하는 기능.
- **챕터 종료 = 「채팅 종료」 버튼** — MVP는 수동 버튼. AI 자동 종료 판단은 추후.
- **AI 응답은 대사 + 지문 혼합** — 몰입감 우선.
- **결과물 = 단편 소설** — 사용자가 읽고 수정 가능.

> ※ 추후 추가 가능성 있음 — 현재(2026-06-08) 팀 결정 기준.
