## 0. 한눈에 — 우선순위 & 응답 흐름

### 0-1. 채팅이 보는 것 — 우선순위 (높을수록 강함)

| 순위 | 무엇 | 강제 수준 | 출처 |
|---|---|---|---|
| **0. 하드 규칙** | **화자 고정**(주인공 대사·행동·내면은 사용자 입력이 전부 — AI가 대신 안 씀) · **JSON 출력** · **한국어만** | 불변 | 주인공 블록 + `CRITICAL_OUTPUT_RULE` |
| **1. 반드시 반영** | **작가 메모** · **캐릭터 행동지시문**(`prompt`) · **호칭 규칙**(`address_rules`) | 강제 | Redis 메모 · `Character.prompt`/`address_rules` |
| **2. 현재 맥락(가장 실질적)** | **지금 입력** + **최근 대화 10턴(원문)** + **줄거리** + **기억 RAG**(오래된 설정 의미검색 재주입) | 높음 | history(Redis) · `story_summary` · `memory.py` |
| **3. 세계관·페르소나** | 제목·장르·배경·규칙 + **작가 문체**(few-shot) | 중 | `World` · `PERSONA_PROMPTS`/`style.py` |
| **4. 참고용(낮음)** | **인물 관계도** — 흐름이 우선, 억지로 유지 안 함 | 약함 | `World.relations` (§7) |

**한 줄:** "지금 입력 + 최근 흐름"이 실질적으로 가장 중요. 그 위에 화자·메모·지시문이 하드 가드로 얹히고, 문체는 작가 페르소나, 관계도는 출발점 참고로만.

### 0-2. 요청 → 응답 흐름 (SSE 파이프라인)

```
[사용자] 주인공 대사 / @조연  ─▶  POST /chats/{id}/messages + GET /chats/{id}/stream
        │
   ① 컨텍스트 조립(서버 권위)
        ├ Redis: 최근 10턴 (PROMPT_HISTORY_LIMIT, 그 이전은 요약+RAG)
        ├ DB: _build_world_context (세계관+인물+호칭+관계[참고]+줄거리)
        ├ 기억 RAG: memory 의미검색 top-k (오래된 설정 재주입)
        └ 작가 메모 + 화자(speaker)
        ▼
   ② 프롬프트 = 페르소나 + 세계관 + 출력규칙 + history + 입력
        ▼
   ③ LLM (Vertex Gemini Flash-lite, json_mode) 스트리밍
        ├▶ event: delta   ← narration 토큰 즉시 흘림 (_partial_narration, 첫 토큰 체감↓)
        ▼
   ④ JSON 파싱 → {narration, dialogue, speaker, protagonist_dialogue,
                  state_changes, story_phase, out_of_genre, genre_note}
        ├ 화자 검증(L1): 장면에 실재하는 인물만 speaker (혼자면 빈 화자)
        ├ 장르 가드: out_of_genre && !genre_open → 칩 노출
        └ 검수 RAG: consistency.check(facts vs reply)  ※ facts에서 관계 블록 제외(§7)
        ▼
   ⑤ event: reply  (최종 구조화 +consistency·memories·genre_note)
   ⑥ event: audio  (나레이션 첫 문장 TTS, 선택)
   ⑦ event: done
        ▼
   ── 응답 먼저 yield 후(TTFB 제외) ── DB 저장 · 줄거리 요약 · 기억 적재 · 작가 리액션(/reaction)
        ▼
[화면] delta→타자기 → reply→나레이션/대사 버블 → 🔍검수배너 · ⚠️장르칩 · ✏️교정칩 · 리액션 자막+🔊TTS
```

## 1. 채팅 스트림 프롬프트 (`GET /chats/{id}/stream`)

### 조립 순서

```
GET /chats/{id}/stream
        │
        ▼
  build_messages()  ←  chats.py
        │
        ├─ [system 프롬프트]
        │   ① CRITICAL_OUTPUT_RULE          story.py
        │      └ JSON 형식 강제 + 미러링 금지
        │
        │   ② protagonist_rule              chats.py (런타임 동적 생성)
        │      └ "사용자는 {주인공이름} 역할 / AI는 {AI인물} 반응만 생성"
        │         ※ session.protagonist_id + Character.is_ai_controlled 기반
        │         ※ session.protagonist_id가 NULL이면 이 블록 전체 미주입
        │
        │   ③ OUTPUT_RULES                  story.py
        │      └ narration / speaker / dialogue / state_changes 스키마 정의
        │
        │   ④ INPUT_RULES                   story.py
        │      └ 사용자 입력 해석 규칙
        │         - 큰따옴표("") 안 = 주인공 대사 (이미 화면에 표시됨, AI dialogue 금지)
        │         - 큰따옴표 밖   = 주인공 행동·상황 묘사
        │
        │   ⑤ WRITER_STYLE_RULE             story.py
        │      └ 소설 문체 지시 (narration/dialogue 분리, 한국어 전용)
        │
        │   ⑥ get_author_prompt(mode="author")   personas.py
        │      └ 작가 페르소나 말투
        │        + [세계관 정보]  (_build_world_context()로 DB에서 조회)
        │        + [등장인물 등장 규칙]
        │        + load_persona_rule() → prompts/persona_rules/*.txt
        │          ※ 현재 persona_rules 폴더 없음 → 빈 문자열 반환
        │
        ├─ [히스토리]
        │   최근 10턴  (PROMPT_HISTORY_LIMIT = 10)
        │   - user    : raw 텍스트 (사용자가 입력한 그대로)
        │   - assistant: AI가 반환한 JSON 텍스트
        │   ※ 히스토리 user 메시지에는 "[이미 화면에 표시됨]" 래퍼 없음
        │
        └─ [현재 user 메시지]
            "[{주인공이름}의 행동·대사 — 이미 화면에 표시됨. 복사 금지]"
            {user_input}
            "[지시] {AI인물}의 새로운 대사·행동만 JSON으로 출력하세요."
```

### world_context 구성 (`_build_world_context()`, chats.py)

> 매 턴 **서버 권위로 DB에서 재구성**(사용자가 보낸 world_context는 무시 → 세계관 수정이 다음 턴 즉시 반영). 조립 순서:

```
1. 세계관 메타        제목 / 장르 / 배경 / 요약 / 규칙
2. 주인공 블록        [사용자 조종 인물 — AI가 절대 대신 서술하지 않음]
                       └ session.protagonist_id 캐릭터 (is_ai_controlled=false)
3. AI 서술 인물 블록   [AI 서술 인물 — 반응·대사를 생성]
                       └ is_ai_controlled=true 캐릭터들 + (여럿이면) 맥락 적합 화자 1인 배분
4. 행동지시문          [캐릭터 행동 지시문 — 반드시 따를 것]   ← Character.prompt
5. 호칭 규칙           인물 간 호칭                          ← Character.address_rules
6. 인물 관계(참고용)   [인물 관계(초기 설정·참고용) … 진행되며 달라졌다면 줄거리·흐름 우선]  ← World.relations (§7)
7. 히든 설정(차로운)   추리 복선                              ← World.hidden_facts
8. 줄거리             [지금까지의 줄거리]                     ← Session.story_summary
```

### AI 응답 JSON 스키마

```json
{
  "narration": "장면 묘사, 행동, 감정 서술 (주인공 내면 추측 금지)",
  "speaker":   "이번 턴 dialogue를 말하는 AI 인물 이름 (없으면 빈 문자열)",
  "dialogue":  "AI 캐릭터 대사만 — 사용자 대사 의미적 반복 금지",
  "state_changes": { "trust_delta": 0, "event": null },
  "internal_note": "서버 저장용 서사 요약 (사용자에게 미표시)"
}
```

## 2. 작가 AI 채팅 프롬프트 (`POST /chats/{id}/author/message`)

```
build_author_messages()  ←  author.py
        │
        ├─ [system 프롬프트]  build_author_system()
        │   PERSONA_PROMPTS (작가 페르소나 기본 설정)   personas.py
        │   + [작가 AI 채팅 모드] 역할 설명
        │   + [세계관]
        │   + [지금까지의 줄거리]

        │   + [스타일 규칙]  load_persona_rule(compact=True)
        │
        ├─ 히스토리 (최근 10턴, 오래된 순)
        └─ 현재 user 메시지
```

> 이 모드는 JSON 응답이 아닌 일반 텍스트로 응답한다.

        ├─ [세계관]
        └─ [입력 형식 해석 규칙]

## 7. 인물 관계도 — '참고용' 정책 (2026-06-17)

채팅이 **정적 관계도에 매이지 않게** 우선순위를 낮춤. 이야기는 진행되며 관계가 바뀔 수 있으므로:

- **생성 프롬프트**: 관계를 `[인물 관계(초기 설정·참고용)]`로 표기 + *"진행되며 달라졌다면 줄거리·현재 흐름을 우선, 억지로 유지·매 장면 끌어들이지 말 것"* → **출발점 정서 힌트**로만 작용.
- **검수 RAG**: `consistency.check`에 넘기는 `facts`(확립된 설정)에서 **관계 블록을 정규식으로 제거** → 관계가 변해도 **모순 오탐 안 함**. (DB 추가조회·지연 없음, `chats.py` 검수 블록)
- 결과: 관계도 = "이렇게 시작했다"는 참고. 흐름이 자유롭게 전개되고 관계 변화 허용.

> 저장 형식: `World.relations` = `[{from, to, label, dx?, dy?}]` (from/to=character.id, dx/dy=라벨 드래그 위치). UI는 설정집 위키 '등장인물' 탭 — [기능 카탈로그](기능_카탈로그.md) 참고.

> ⚠️ §5 '알려진 문제'의 일부 항목은 이후 해소됨(화자 검증 2겹, 검수 RAG 화면 노출 등) — 최신 상태는 §0·§7 기준.
