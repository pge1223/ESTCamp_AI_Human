# KoELECTRA 보이스피싱 탐지 모델 작업 메모 (v6)

> 작성일: 2026-05-13
> 모델: `monologg/koelectra-base-v3-discriminator` (멀티라벨 파인튜닝)
> 이전 버전 대비 변경: **Hard Negative 정상 데이터 1,500개 추가** (오탐률 감소 목적)

---

## 1. v6 변경 요약

v5에서 오탐이 발생한 핵심 원인은 **피싱 키워드(인증번호, 계좌, 이체 등)가 포함된 정상 발화**를 모델이 피싱으로 오인하는 것. v6는 이를 해결하기 위해 피싱과 표현이 유사하지만 실제로는 정상인 "Hard Negative" 데이터를 집중 추가.

---

## 2. 추가 학습 데이터 (`data/v6/`)

### 2-1. 데이터 특성

- **목적**: 피싱 키워드 포함 정상 발화에 대한 오탐 감소
- **라벨**: 전부 `[0, 0, 0]` (정상)
- **특징**: 인증번호, 계좌번호, 주민번호 등 피싱 유사 키워드를 포함하지만 실제 정상 금융/서비스 발화

| 코드 | 카테고리 | train | val | test |

### 2-3. 샘플 예시

```

[0, 0, 0] "카드 결제를 하려고 하는데, 인증번호가 필요해서 문자를 받아야 하거든요."
[0, 0, 0] "연금 가입 확인을 위해 본인 인증 절차를 진행해야 해요. 주민번호 앞 두 자리를 알려주시면 확인해 드리겠습니다."
```

## 4. 남은 작업

### 4-1. 성능 평가

`test_scripts/run_mixed_test.py` 로 v5와 동일한 조건에서 비교 평가.

- `mixed_test_03.json` — 탐문형 FN 검증
- `mixed_test_v4.json` — 일반 혼합 데이터셋
- 확인 포인트: hard negative 추가 후 **오탐(FP) 감소 여부**, **탐지율(Recall) 유지 여부**

### 4-2. int8 양자화 (Docker)

```bash
docker-compose up -d
docker exec -it vp-detector bash
python model_build/convert_int8_docker.py
```

- 목표 크기: 50~100MB 이하
- v5 int8 변환 시 erf 연산 문제로 `model_int8_no_erf.tflite` 사용한 전례 있음 → 동일 이슈 확인 필요
- 변환 성공 시 실기기 추론 속도 확인 (목표 80ms 이하)
