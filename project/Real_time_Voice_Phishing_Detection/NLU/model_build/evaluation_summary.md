# NLU 모델 성능 평가 정리

## 테스트 환경

- **테스트셋**: mixed_test_v4.json — 4,390개 (피싱 303 / 정상 4,087)
- **모델**: monologg/koelectra-base-v3-discriminator (Base) vs koelectra-finetuned-v5 (FT)
- **파이프라인**: 키워드 필터 (score ≥ 15) → KoELECTRA 추론
- **임계값**: danger_level ≥ 0.5

---

## 평가 관점 두 가지

파이프라인 구조상 평가 관점이 나뉩니다.

```
4,390개 입력

  379개 KoELECTRA 투입   ← [모델 단독 평가 구간]
    ↓ KoELECTRA 추론
  결과 출력
              ↑
[파이프라인 전체 평가 구간]
```

## 1. 모델 단독 성능 (트리거된 379개 기준)

키워드 필터를 통과한 샘플만 모델이 실제로 보는 구간.
두 모델이 동일한 379개를 보고 어떻게 분류하는지 비교.

```
트리거된 379개 구성:
  실제 피싱: 244개
  실제 정상: 135개
```

|  | Base | FT v5 |
|---|---|---|
| TP | 226 | 244 |
| FP | 126 | 2 |
| FN (모델 단) | 18 | **0** |
| TN | 9 | 133 |
| Precision | 0.642 | **0.992** |
| Recall | 0.926 | **1.000** |
| F1 | 0.758 | **0.996** |

**해석:**
- FT 모델은 테스트셋 라벨 기준 피싱을 **모두 탐지 (FN=0)**
- Base 모델은 피싱 18건 미탐, 정상 126건 오탐 (거의 무작위 수준)
- FT 오탐 2건은 테스트셋 안에서 측정된 수치 — 실제 서비스에서는 더 많을 수 있음

> ⚠️ **FN=0, FP=2의 한계**: 테스트셋에 없는 현실 케이스는 측정되지 않음.
> 예) "마포구청 형사입니다. 신분증 분실 신고가 들어와 연락드렸습니다." — 실제 공무원
> 발화라면 정상이지만 모델은 기관사칭으로 탐지할 가능성이 높음 (숨겨진 FP).
> 테스트셋 라벨 품질과 커버리지에 종속된 수치임을 감안해야 함.

**해석:**

- FT 모델 기준 Recall 80.5%가 낮아 보이지만, 미탐 전부 키워드 필터 단에서 발생
- 키워드 필터 개선 시 Recall 추가 상승 가능

## 3. 미탐(FN 59건) 원인 분석

키워드 필터 미통과 원인: 피싱 키워드 없이 문맥만으로 피싱인 발화.

**예시:**
```
"안녕하세요! 저희는 소비자원입니다. 오늘 중에 서류를 제출하셔야 지원을 받을 수 있습니다."
→ score=0 → KoELECTRA 미도달 → 자동 정상 처리
```

**보완 방향:**
- 테스트 문장이 짧고 단편적이어서 키워드 미노출
- 실제 통화에서는 fulltext(전체 문맥)로 입력 → 앞뒤 발화에서 키워드 등장 가능성 높음
- 키워드 목록 확장 또는 필터 임계값 조정으로 커버리지 향상 가능

## 4. 오탐(FP 2건) 원인 분석

정상인데 피싱으로 판정된 2건:

| 문장 | 오탐 이유 |
|---|---|
| "성함과 주민번호 앞자리를 말씀해 주시면…" | 은행 상담 문맥이나 개인정보 패턴에 반응 |
| "이체하려고 하는데 비밀번호가 생각이 안나네요" | 금전·개인정보 패턴 혼동 |

**보완 방향:**
- 금융 상담·은행 업무 정상 발화 학습 데이터 추가
- 현재 오탐률 2/4,087 = **0.05%** — 실서비스 배포 요건 충족 수준
